An anonymity network you can check for yourself

HidraNet is an open-source overlay network: onion routing over a post-quantum handshake, a Sybil-resistant DHT, self-certifying .hidra services, end-to-end encrypted applications and HidraVPN. This paper describes what is built, how it works, and, just as plainly, what it does not do yet. Every claim in it points at code anyone can run.

Abstract

What this paper is

HidraNet combines onion routing with a hybrid post-quantum key exchange (X25519 + ML-KEM-1024), a Kademlia DHT hardened with the S/Kademlia defences, self-certifying hidden services and a suite of applications that encrypt on the device. HidraVPN, built alongside it, routes a whole machine through one or two independently run WireGuard nodes behind a kill switch. The reference implementation is a Rust network engine (hidra-node), the HidraVPN workspace and a desktop browser.

We state one thing first, because a whitepaper that overstates is worse than none: today, exit anonymity in HidraBrowser is provided by the Tor network, which the browser bundles. The HidraNet protocol layer is implemented and tested; its relay population is not yet large enough to provide anonymity on its own. Section 12 sets out how that changes.

Post-quantum transport

Traffic recorded today can be stored and decrypted the day a cryptographically relevant quantum computer exists. The only defence that works against harvest now, decrypt later is a key exchange that is already quantum-resistant when the recording is made. HidraNet's is.

The hybrid is the transport handshake itself, not a layer beside it: Noise_XXhfs_25519+MLKEM1024_ChaChaPoly_BLAKE3. The first message carries an ephemeral ML-KEM-1024 encapsulation key next to the X25519 ephemeral; the second carries the ciphertext, and the shared secret is mixed into the chaining key right after ee, before the responder's static key is encrypted. An adversary with a recording and a quantum computer breaks the X25519 half and still cannot read the static key, let alone the traffic.

Why ML-KEM and not Kyber. The engine used pqc_kyber until an audit of the dependency tree found two unfixable advisories: an AVX2 backend that skipped implicit rejection, handing a chosen-ciphertext attacker the decapsulation key, and KyberSlash timing leaks. The crate was unmaintained, so it was replaced with the FIPS 203 implementation rather than pinned. cargo audit runs in CI on every change.

Onion routing

Traffic crosses a circuit of three relays. The client wraps each message in one layer per relay (ChaCha20-Poly1305, a fresh key per hop from that hop's handshake), and each relay removes its layer. In the design, a relay learns only the hop before it and the hop after it, so no single relay knows both who is talking and what they are talking to.

The circuit builder does not deliver that yet. Today the client opens a direct connection and a separate handshake to each of the three relays, with the same client static key on every hop. So every relay on the circuit sees the client's address, and the shared key lets the three relays link their views of the same client. The layers still keep the payload from all but the last relay, but the unlinkability the design promises is not there. The fix is telescoping construction, as in Tor: the client connects only to the entry and extends through it, hop by hop, with a fresh ephemeral key for each hop. It is the first item on the roadmap (§12).

Not yet. Circuits are not yet extended through the entry, as described above. Cells are not padded to a fixed size on the wire and there is no cover traffic, so the size and timing of a page load cross the network largely intact. The padding code exists and is tested, and is not yet on the data path. Circuit construction does not yet pin each relay's static key against a published one; announcing that key through the DHT and checking it is on the roadmap.

5

A DHT that resists Sybils

Peers and services are found through a Kademlia DHT, with no central server. A plain Kademlia has a well-known weakness: node IDs are free, so one operator can mint thousands of them right next to a service's key, own the set of nodes closest to it, and hide the service or point it somewhere dead. HidraNet puts the S/Kademlia defences on the wire.

IDs cost work, bound to a key

A node ID is the first 20 bytes of BLAKE3("hidra/node-id/v1" ‖ public key ‖ nonce), valid only when the rest of that hash starts with 24 zero bits. The ID is unknown until the work is done, so closeness cannot be tested for free.

Signed, and bound to the signer

Every DHT message is signed with Ed25519. The sender's key must be the signing key and its ID the one that key and nonce derive. Every node named in an answer is checked the same way before it is asked anything.

Seated only where it answers

A node that writes first is seated after it answers a fresh ping at the address it wrote from. A signed packet replayed from elsewhere seats nothing. Checks are budgeted per network and backed off per host.

Three disjoint paths

Lookups are dealt to three paths that never ask the same node, seeded one network at a time. Service lookups walk until the 60 closest nodes they have seen have answered, within fifteen seconds.

One network, a few seats

At most two nodes from one IPv4 /24 (or IPv6 /48) per bucket and ten per table, counted at the address the node answered from, not the one it claims.

Records signed by the service

A .hidra descriptor carries the service's own signature, expires an hour after signing and is republished every fifteen minutes. A node in the path can withhold a record; it cannot forge one.

What an attack costs

Landing one identity among the K = 20 closest to a key in a network of N nodes costs about (N / 20) × 224 hashes; the whole closest set, twenty times that. On one server core, one identity takes about 1.2 seconds. Proof of work alone is therefore cheap for a patient attacker, and it is not what carries the weight: hiding a service also takes addresses in more than sixty distinct networks, seated in honest tables, winning on all three paths.

What this does not do. An operator with enough hardware and addresses in many networks can still hide a service, from some clients or from all; it cannot forge one. A client whose every path starts at attacker nodes can be misled. DHT queries still leave from the user's own address; routing them through a circuit is on the roadmap.

Each defence is covered by a test that fails when the defence is removed: 15 DHT integration tests, attack scenarios included, run against real sockets.

6

.hidra services

A .hidra address is the 160-bit BLAKE3 hash of the service's public key. The name is the key: there is no certificate authority to trust and no registrar who can take it away. Resolution is checked by the client itself: a descriptor that the service's key did not sign is refused, and the client keeps the highest revision it can verify. A descriptor names up to eight introduction points, so the host's own address is never published. SevenNine builds and hosts the sites; deleting one withdraws its record, which is gone from the network an hour after it was last signed.

8

HidraVPN

The browser protects what happens in the browser. HidraVPN protects the whole machine. It is WireGuard, run as a background service, through nodes run by different people, with a kill switch that is on by default.

A different identity for every node

Each node is shown a key derived for it from one master key with HKDF-SHA256. No node sees the master key, and two operators comparing peer lists find nothing in common.

Kill switch, including between circuits

nftables on Linux, the Windows Filtering Platform on Windows. IPv6 is blocked, DNS is pinned to the node's resolver, and nothing passes for merely being an established connection. When a circuit is rebuilt for a new identity, a hold allows only the old and the new first hop until the new rules replace it.

Nodes from a signed list

A new client learns which nodes exist from a list signed with Ed25519, checked against a key built into the client before a byte of it is read. Lists carry a sequence and an expiry; an older or expired list is refused, and a newer one follows a node that moved.

Open admission, with limits

A stranger connects on the first try: a node that admits openly issues an invite on request, at most three per address and 120 per node every ten minutes, up to 4,000 leases. A lease with no handshake lapses within fifteen minutes.

Nothing recorded Tested

No node or service log names an address, a name looked up or a byte of traffic. The network test suites grep every log for them.

Protecting the machine

  • Local services cannot be reached by web pages. Everything listens on loopback and screens Host and Origin, so a page cannot reach it by DNS rebinding.
  • Keys at rest. Secret keys are created readable by the owner only. With a passphrase set, they are sealed with XChaCha20-Poly1305 under a key from Argon2id.
  • The browser's own secrets live in a vault on the operating system's keychain, one compartment per app.
  • Logs that cannot betray. Peer addresses, destinations, mail addresses, nicknames and payloads are scrubbed before they reach a log; a test fails if any log line would write one.
  • Fingerprinting. Each tab gets one coherent profile (system, GPU, screen, timezone, language chosen together), deterministic canvas noise, masked WebGL renderer, and no client-hint headers. WebRTC is held to the proxy in the network stack. The profile is injected when the page's DOM is ready, not yet at document start; that is on the roadmap.
  • Releases you can check. Release files are signed with Ed25519; the browser verifies them with a key built into it, in the same format the command-line tool uses.

Threat model

A threat model that does not say what it does not protect against is advertising, not engineering.

Protected against

AdversaryWhat they get
Your local network or ISPEncrypted traffic to an entry point; neither destination nor content
The site you visitAn exit's address, not yours; a fingerprint that changes per tab
One relay in the middleBy design, the previous and the next hop only. Today it also sees the client's address (§4)
Someone recording today for a quantum computerNothing: the handshake needs ML-KEM to fall too
A message transport operatorCiphertext without a key
A Sybil operator in the DHTThe power to withhold a record, not to forge one
A web page attacking local servicesA refusal: loopback services screen Host and Origin

Not protected against

ThreatWhy
An adversary watching both endsTiming correlation defeats every low-latency network, Tor included
A small networkAnonymity is a crowd; a few hundred users is a small one
Relays comparing notesCircuits are not yet telescoped: each relay sees the client's address and the same client key (§4)
Traffic shapeNo fixed-size cells on the wire yet and no cover traffic
Relays run by one partyNo directory authorities or consensus yet; the largest architectural gap
A malicious exitIt sees what is not end-to-end encrypted. Use HTTPS
A compromised deviceThe keys are on it
What you publish yourselfNo network can hide what a person reveals

If being identified would put you in danger, use Tor. HidraNet is young and has not been audited by anyone outside the project. The browser ships with Tor built in for exactly this reason.

Licence and governance

All of it is under the MIT licence. The protocol is a common good: anyone may implement it, audit it, fork it and run nodes. The company develops software and services and does not operate exit nodes; the network is meant to be run by volunteers, as Tor's is.
