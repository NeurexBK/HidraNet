Checking
A signed list tells you which nodes exist and who runs them. A node that admits openly admits this machine when you join it, or when you press Connect with nothing joined yet; a node that admits with a pass takes one pass per connection, which sudo hidravpn passes get asks the list's issuer for, and the issuer never learns which node a pass is for; a node that admits by hand needs its operator, who hands you an invite for hidravpn nodes add.

Passes

A node that admits with a pass takes one per connection, and sees a new key every time. Passes come from the issuer the signed list names, against an account: the issuer counts them but never learns which node a pass is for, and a node never learns whose account it came from.

The token is handed to the service on this machine, which keeps it where only an administrator can read it; this page does not keep it. Anyone with an account on this computer can spend the account's passes.

Release files

A downloaded HidraVPN file is only worth running if its signature checks out against the release key built into this browser. Choose the file; its .sig must sit beside it.

This page does not contain the VPN. It drives the HidraVPN service installed on this machine; with no service, nothing here can connect. Anyone with an account on this computer, and any program they run, can switch HidraVPN on or off for the whole machine. Strong privacy, not anonymity: the service says what each node sees, and so does this page.
